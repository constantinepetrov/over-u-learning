# OVER U: результат первого технического этапа

Проверено 8 октября 2026 года в managed Linux environment. Рабочий checkout: `/workspace/over-u-learning`, ветка `over-u/development`. Официальный upstream — https://github.com/frappe/lms, база — `v2.64.0` (`7c46bb8f4976222b3f6aa84368551c424edaa194`).

Development-школа запущена. Существующие возможности и интерфейсы LMS сохранены; полный redesign не выполнялся. **Удалённый GitHub fork ещё не создан:** доступный connector не предоставляет fork API, а запрос GitHub CLI к `api.github.com` блокируется Forbidden. Локальная ветка и remote upstream подготовлены; origin/push отсутствуют. Это остаётся незавершённой частью запроса, инструкции продолжения есть в README.

## Что запущено

Docker Compose: Frappe/Bench, MariaDB 10.8, Redis 7. Приложения: Frappe 16.51.0, payments (version-16, pinned commit), LMS 2.64.0, OVER U 0.1.0. Runtime Python 3.14.8, Node 24.19.0, Bench 5.31.0. HTTP: `http://over-u.localhost:8000/lms`, loopback среды. Это не публичная опубликованная школа: для рабочего компьютера нужен port forwarding либо локальный запуск.

Созданы и проверены входы:

| Назначение | Пользователь | Доступ |
|---|---|---|
| Администратор | `Administrator` | Административный аккаунт Frappe |
| Преподаватель | `teacher@over-u.example.com` | Course Creator, instructor нашего курса |
| Ученик 1 | `student1@over-u.example.com` | LMS Student, Enrollment |
| Ученик 2 | `student2@over-u.example.com` | LMS Student, Enrollment |

Пароли находятся только в `/workspace/over-u-runtime/dev.env` (режим 600), вне Git. Для admin используется OVER_U_ADMIN_PASSWORD; для трёх demo-пользователей OVER_U_DEMO_PASSWORD. Настоящих учеников и учебных персональных данных здесь нет.

Курс «OVER U — Основы осознанного обучения» (`over-u`):

| Модуль | Уроки |
|---|---|
| 1. Начало | 1.1 текстовое приветствие; 1.2 локальное демонстрационное видео |
| 2. Проверка знаний | 2.1 текст об измеримой цели; 2.2 тест из четырёх вопросов, проходной балл 75% |
| 3. Практика | 3.1 текстовая домашняя работа; 3.2 итоговый урок |

Все шесть уроков обязательны и проходят последовательно. Видео взято из штатных assets Frappe Learning для демонстрации плеера, это не готовый видеокурс OVER U. Попытки теста не ограничены. Домашняя работа открывает следующий урок только после Pass преподавателя.

## Что подтверждено проверками

**9 интеграционных тестов OVER U + 41 upstream тест прошли.** Upstream: 38 проверок lesson locking и 3 проверки запрета самостоятельного выставления оценки. Это целевые проверки, а не полный test suite Frappe Learning. Логи: [OVER U](../evidence/policy-tests.log), [upstream](../evidence/upstream-tests.log).

Проверены: запрет пропуска урока; 50% в тесте не открывают следующий урок, 75% открывают; отправка домашней работы не равна зачёту; собственную работу нельзя зачесть себе; чужой Course Creator не может оценить работу в OVER U курсе; generic запись progress не обходит Pass; неверный course в save_progress отклоняется; утверждённый ответ нельзя заменить; исправление после Fail возвращает Not Graded; отмена Pass снова закрывает ещё не завершённый следующий урок; выключенное opt-in поле сохраняет штатную семантику.

**Браузерный сценарий прошёл в Chromium без pageerror.** Ученик ответил на четыре вопроса через штатный UI и получил 75%; отправил ответ из встроенного Assignment; увидел Not Graded. Преподаватель открыл dashboard, редактор и список работ, поставил Pass и оставил комментарий. Следующий урок открылся без повторной отправки ученика. Подтверждены работа видеоплеера, независимость progress двух пользователей и вход администратора.

Для первых трёх текстового/видео уроков автоматизация вызывает штатный save_progress API, чтобы не ждать dwell timer. Поэтому сценарий подтверждает API завершения и отображение/воспроизведение видео, но не подтверждает защиту обязательного просмотра целиком. Тест и домашняя работа отправлены через UI. После последнего урока итоговый progress ученика 1 — 100%; ученика 2 — 0%, пять уроков закрыты. Промежуточные скриншоты сохраняют состояние до окончания курса.

Данные доказательств: [browser-validation.json](../evidence/browser-validation.json), [runtime-summary.json](../evidence/runtime-summary.json), [demo-manifest.json](../evidence/demo-manifest.json). [Все 15 экранов](SCREENS.md) и [HTML-галерея](../evidence/index.html) показывают ученика, преподавателя, редактор, урок, видео, тест, отправку и проверку Assignment.

Сборка Frappe/LMS assets завершилась успешно. Python source compilation, синтаксис init.sh и git diff --check прошли. После перезапуска контейнера Frappe сайт ответил HTTP 200; повторный seed сохранил demo, зачёт и progress 100%/0% в named volumes. Независимый повторный bootstrap на полностью пустых volumes и нагрузочное тестирование в этом этапе не выполнены. Базовые Docker image tags и apt packages не зафиксированы digest/snapshot: это development-конфигурация, не полностью воспроизводимый production build.

## Что доступно из коробки и что добавлено

Из коробки работают роли/пользователи, курс/модули/уроки, EditorJS, текст/видео, тест и серверный балл, отправка/проверка домашних работ, Enrollment, проценты, последовательный доступ, dashboard преподавателя. Существующие Programs, Batches, Certifications и остальные возможности не удалены.

Для требования OVER U «дождаться зачёта» добавлено отдельное Frappe-приложение, opt-in поле курса, серверные hooks проверки/пересчёта progress и тонкий override save_progress с делегированием upstream. Core patch — четыре добавленные строки и замена одной строки в get_assignment_progress, универсальная точка дополнительных фильтров. Скопированных LMS controllers и глобальных monkey patches нет. Штатная проверка Assignment считает любую submission достаточной, независимо от Pass — это главный обнаруженный функциональный разрыв.

Подробная [карта файлов, компонентов, API и моделей, аудит Assignment и риски обновления](ARCHITECTURE.md) объясняет реализацию.

## Ограничения и следующий этап

Student-facing UI можно полностью заменить отдельным SPA в приложении OVER U на `/school`, сохранив существующие DocType, серверную оценку теста, progress, cookie/CSRF и права. Рекомендуется тот же origin и сохранение `/lms` преподавателю и `/desk` администратору. Backend API не обещают внешнюю стабильность: нужен pinned релиз и контрактные проверки при обновлении. Новый develop требует Frappe 17 и имеет другой индекс размещений assessments.

Перед публичным запуском нужны проверки приватности домашних вложений и границ преподавательского доступа, generic REST и lesson/instructor_content/quiz payloads. В metadata релиза включён make_attachments_public; нельзя обещать приватные домашние файлы без доработки. Проверенный текстовый сценарий и Pass gate не заменяют полный security audit. Также не проверены параллельные grading/resubmission и нагрузка.

Штатная последовательность относится ко всем урокам; optional/branching требуют отдельного правила. API завершения не доказывает просмотр/усвоение. Отмена Pass сохраняет уже завершённые последующие уроки; нужен согласованный порядок отзыва прогресса и сертификатов. Production hosting, backups, домен, email, платежи и видеохостинг предстоит настроить. Сохраняется AGPL-3.0-or-later upstream.

Предлагаемый следующий этап: создать и опубликовать remote fork после восстановления GitHub доступа; добавить CI и воспроизводимый fresh bootstrap; согласовать required/optional, retry и отмену зачёта; закрыть security/privacy разрывы выбранного релиза; затем разработать один полноценный student flow OVER U на `/school`. Расширять UI после проверки сквозного пути «курс → урок → тест → домашняя работа → Pass → следующий урок».

# OVER U Desk setup and Russian localization (stage 2.2)

## What changed

- Russian is enabled in Frappe's native `Language` records while `System Settings.language` remains `ru`. This makes Russian available in setup and user selectors; an explicitly selected `en` is preserved.
- The native Russian catalog in `over-u/apps/over_u/over_u/translations/ru.csv` gained targeted Frappe Desk strings. Learning-specific labels are reviewed in context. User list type labels use Frappe's `doctype_list_js` extension; the stored `System User` / `Website User` and LMS role identifiers do not change.
- The isolated localization app remains the owner of custom LMS translations and after-build adaptations. Framework and LMS source trees are not patched.
- The development Bench can resolve more than one `*.localhost` site. This allows Desk setup to run on a separate restored site and keeps the source POC site intact.

## Setup procedure

Frappe's normal setup wizard remains responsible for country, timezone, currency, language, and completing the native site setup. For an already populated school, prepare an independently restored clone before opening that wizard. LMS's standard first-run callback also imports demo data and promotes an existing account to Moderator, so the clone-only `over_u.desk_validation.prepare_existing_school_setup` helper records LMS's native setup-complete marker before the Framework wizard starts. It checks that the expected OVER U course and both enrollments exist and that only the dedicated `over-u-desk.localhost` site is targeted. Framework's wizard is then completed normally; no setup flag is bypassed.

The current development verification restored the pre-stage backup to `over-u-desk.localhost`, retained the target site's generated DB identity and admin credentials, and copied only the encryption key required by Frappe's encrypted fields. The original site and the permanent Drive backup were not used as wizard targets. The private archive is deliberately excluded from this repository.

After the wizard, the administrator's native User preferences on the clone point to the `OVER U` app and `Users` workspace. New clones should set these two fields for `Administrator` through the ordinary User profile form; this is per-user navigation state and does not change site roles.

## Desk scope and known limits

The browser audit covered the native Users workspace and user list/form, user role editor, Role Permissions Manager, LMS course and enrollment lists, LMS Settings, Website Settings, and System Settings. The Russian catalog improves these standard views, including search prompts, validation text, role display names, profile labels, settings, and activity labels.

This does not claim complete translation of every Framework workspace, every optional app, custom report, user-authored Workspace, or every notification generated by every installed app. Some fields deliberately display technical identifiers in Developer Mode; these are diagnostic names, not translated user-facing labels. The role and DocType identifiers remain in English where they are the actual stable value used by permissions, APIs, and records. Optional payment, mail delivery, external integrations, and production details remain unconfigured.

The integration test `over_u.test_desk_users` exercises native user creation, the Russian default, teacher role assignment/removal, enable/disable, and User DocType permission boundaries with disposable records inside a rolled-back test transaction. `over-u/dev/desk-capture.mjs` records the stock browser forms and settings; `over-u/dev/desk-access-e2e.mjs` verifies administrator routing and confirms that students and teachers cannot see the OVER U Desk entry or read User records. `over-u/dev/desk-setup-wizard.mjs` drives the actual wizard in the restored clone. Student/teacher browser regression uses the existing stage-2.1 E2E harness with `OVER_U_BASE_URL`, `OVER_U_EVIDENCE_DIR`, and `OVER_U_DESK_SETUP_COMPLETE=1` set for the clone.
